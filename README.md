# ShoPlanner backend

Shared shopping lists: products, favorites, shop maps and product lists with real-time updates over WebSocket.
A single Gin HTTP service (`cmd/backend`) on top of an embedded SQLite database.

## Requirements

- Go 1.25+
- **CGO enabled** and a C toolchain — the SQLite driver (`mattn/go-sqlite3`) is a cgo package.
  On Alpine that means `build-base` and `sqlite-dev`.
- Python 3 — the code generators are invoked through the shims in `tools/`.
- [Task](https://taskfile.dev) for the build targets below, `golangci-lint` for `task lint`.

## Build

```bash
# regenerate swagger docs, enums and sqlc queries
task generate
# compile into bin/backend
task build
# build and run against the config in this repo
task run
```

`task build` runs `task generate` first. The generated files are committed, so a plain
`go build ./...` (or the Docker image) works without Python and without the code generators.

Other targets: `task lint` (golangci-lint), `task fmt` (`swag fmt` + `go fmt ./...`),
`task export` (writes the Docker image to `shoplanner.tar`).

## Configuration

The service reads two independent sources; both are required.

### Config file

Path is given by `--config` and defaults to `/etc/backend.yaml`. A development copy lives in `config/backend.yml`:

```yaml
listener:
  port: 3000
  host: 0.0.0.0
  net: tcp
auth:
  refresh_token_livetime: 4000h
  access_token_livetime: 24h
```

### Environment

| Variable            | Required | Meaning                                                                 |
|---------------------|----------|-------------------------------------------------------------------------|
| `DB_PATH`           | yes      | Path to the SQLite database file. It is created on first run.            |
| `AUTH_PRIVATE_KEY`  | yes      | **Path** to a PEM file with a PKCS#8 ECDSA private key used to sign JWTs. |
| `LOG_NO_SYSLOG`     | no       | Any non-empty value logs to stderr instead of syslog.                    |

Variables can be exported normally or put into a `.env` file for `docker compose`.

Generating a signing key:

```bash
openssl ecparam -name prime256v1 -genkey -noout -out ec.pem
openssl pkcs8 -topk8 -nocrypt -in ec.pem -out auth_key.pem && rm ec.pem
```

Example `.env`:

```bash
DB_PATH="/var/lib/shoplanner/shoplanner.db"
AUTH_PRIVATE_KEY="/var/lib/shoplanner/auth_key.pem"
LOG_NO_SYSLOG=1
```

## Docker

```bash
docker compose up -d
```

The compose file reads `./.env`, publishes port 3000 and mounts the project directory into
`/var/lib/shoplanner/`, so `DB_PATH` and `AUTH_PRIVATE_KEY` should point inside that directory.
The image bakes `config/backend.yml` in as `/etc/backend.yaml`, which is the default config path.

## systemd

`config/systemd/shoplanner.service` runs `/usr/bin/shoplanner --config=/etc/shoplanner/backend.yml` and
presets `DB_PATH` to the unit's state directory. `AUTH_PRIVATE_KEY` is not set by the unit — supply it
via a drop-in or an `EnvironmentFile`, otherwise the service fails to start.

## API

Everything is served under `/api/v1`. Swagger UI: `/api/v1/swagger/index.html`
(sources in `docs/`, regenerated by `task generate`).

Authenticated endpoints expect the token in an **`Auth`** header (not `Authorization`):

```
Auth: Bearer <access token>
```

| Endpoint                                  | Auth | Description                        |
|-------------------------------------------|------|------------------------------------|
| `POST /auth/login`                        | no   | Issue access and refresh tokens    |
| `POST /auth/refresh`                      | no   | Exchange a refresh token           |
| `POST /auth/logout`                       | yes  | Drop the session                   |
| `POST /user/register`                     | no   | Create a user                      |
| `GET /user`                               | admin| List users                         |
| `POST /product`, `GET`/`PUT /product/id/:id`, `GET /product/list/:ids` | yes | Products |
| `/favorite/...`                           | yes  | Favorite product lists             |
| `/shopmap/...`                            | yes  | Shop maps and category order       |
| `/lists/...`                              | yes  | Product lists, members, item states |
| `GET /lists/:id/ws`                       | yes  | WebSocket stream of list changes   |

List changes are pushed to every subscriber of a list over the WebSocket endpoint. The subscription
registry is in-memory, so the service is currently single-instance.

## Layout

```
cmd/backend            entry point and the only wiring of repos -> services -> handlers
internal/backend/<domain>/{model.go,repo,service,api}
pkg                    shared helpers: typed ids and dates, error sentinels, REST helpers, hashing
config                 backend.yml, sqlc.yaml, systemd unit
tools                  Python shims for go-enum and sqlc, called from //go:generate
docs                   generated swagger (do not edit by hand)
```
